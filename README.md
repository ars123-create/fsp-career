## Запуск с Docker

Нужны Python 3, Docker с Compose v2 и доступ к реестрам пакетов при первой сборке. Из корня распакованного `fsp-career`:

```sh
python3 scripts/setup.py
docker compose up -d --build
```

Приложение: <http://127.0.0.1:8019>; API: <http://127.0.0.1:8019/docs>; демо-почта Mailpit: <http://127.0.0.1:8026>.

Войдите через `/login`: `candidate@demo.fsp.test` или `employer@demo.fsp.test`, пароль обоих — `12345678`. Это вымышленные аккаунты, доступные только в деморежиме. [Памятка проверки](docs/TEST_ACCOUNTS.txt). Для нового аккаунта зарегистрируйте адрес и откройте письмо в Mailpit. Письма наружу не отправляются. Настройка создаёт случайные секреты в `.env`, сохраняет существующие и не печатает их. PostgreSQL хранится в volume. Остановить без удаления данных: `docker compose stop`.

Порты 8019/8026/1026/5434 должны быть свободны. Если старый проект уже запущен, не заменяйте его базу новыми секретами: выберите отдельное имя (`docker compose -p fsp-review ...`) и свободные порты в копии `compose.yaml`. `FSP_PORT` меняет порт приложения; остальные опубликованные порты меняются в Compose.

## Без Docker

Проверено с Python 3.14 / Node 24. Из корня:

```sh
sh scripts/start.sh
```

Адрес <http://127.0.0.1:8018>, SQLite `data/fsp.db`. Скрипт устанавливает зависимости по lock, собирает frontend и применяет миграции. Порт 8018 должен быть свободен. Без SMTP письмо доступно по приватной демо-квитанции в интерфейсе — это не проверка владения внешним ящиком.

Для публичного пилота нужны SMTP, HTTPS, `FSP_DEMO_MODE=false`, правильный `FSP_FRONTEND_URL`, отдельная база и политика обработки данных. Локальные проверки не означают production readiness.

## Возможности

- Два кабинета; email-подтверждение, восстановление пароля, смена email, отзыв сессий.
- Профиль, согласия, публикация, текстовый PDF-импорт с предпросмотром, PDF с кириллицей.
- Backend и аналитика данных, Junior/Middle; 12 заданий, 6 практических. Короткая форма из 3 практических задач, история, сохранение ответов. Грейд меняет только основная оценка; неудача не понижает достигнутый грейд.
- Фильтры, объяснения, m6 и прежние режимы весов/уточнений, сохранение запросов и повторная проверка приватности. m6: до 100 подходящих профилей, 1–3 навыка, до пяти результатов.
- Предложение без вакансии, обязательная вилка RUB, принять/отклонить/отозвать. API и PDF проверяют разрешение конкретной компании. Дополнительно — вакансии и самостоятельные отклики.
- Демонстрационный адаптер ФСП; ID не обязателен и не присваивает грейд. ATS описана как концепция API/событий.
