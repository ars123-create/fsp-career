# Модель и доказательства

Все гарантии ниже условны: неизвестные истинные приоритеты и признаки должны
лежать в объявленных множествах, полезность аддитивна, признаки сопоставимы.
Ни одна теорема не доказывает эффективность найма реальных людей. SciPy
вычисляет float64-приближение; статусы solver и абсолютный gap публикуются.

## 1. Определение

Кандидаты i=1…n уже прошли одинаковые обязательные фильтры. Признак t имеет
значение θ_it ∈ [ℓ_it,u_it] ⊆ [0,1]. Допустимые веса w лежат в непустом
компактном многограннике W ⊆ {w≥0, Σw=1}. Для заданного мира
U_i(w,θ)=Σ_t w_t θ_it. Для множества S размера k определим

    R(S) = max_{w∈W, θ∈[ℓ,u]} [max_{|T|=k} Σ_{i∈T} U_i − Σ_{i∈S} U_i].
    S* ∈ argmin_{|S|=k} R(S).

Суммируем полезность всех k рассмотренных профилей. Это отличается от SMR,
который оценивает лучшего одного из представленных вариантов. Порядок внутри
S не входит в цель. Рейтинг грейдов, зарплата и контакты не являются θ.

## 2. Точный худший сценарий признаков

**Утверждение 1.** Для фиксированных S,w максимум по θ достигается одновременно
для всех T, если θ_i=ℓ_i при i∈S и θ_i=u_i иначе.

**Доказательство.** В разности сумм коэффициент θ_it равен
w_t(1[i∈T]−1[i∈S]). В T\S он неотрицателен, в S\T неположителен, в
пересечении равен нулю. Поэтому выбранные границы максимизируют разность для
каждого T. Один и тот же угол подходит всем T; максимум по T не меняет выбор.
Независимость координат интервального ящика и w≥0 существенны. □

Пусть a_i(w,S)=w·ℓ_i для i∈S, иначе w·u_i. Тогда

    R(S) = max_{w∈W} [TopKSum(a(w,S)) − Σ_{i∈S} w·ℓ_i].

## 3. Достаточность вершин

**Утверждение 2.** В этой формуле достаточно максимума по вершинам W.

**Доказательство.** Для каждого фиксированного T разность линейна по w.
Максимум конечного числа линейных функций выпуклый. Если w — выпуклая
комбинация вершин, значение функции не больше соответствующей комбинации
значений в вершинах и тем более не больше их максимума. Обратное неравенство
следует из принадлежности вершин W. □

Это рассуждение НЕ применимо к max(лучший вне набора − лучший внутри набора)
SMR: там другая функция, и максимум может находиться не в вершине.

## 4. Компактная точная MILP

Обозначим вершины v=1…m, L_vi=v·ℓ_i, U_vi=v·u_i, x_i=1[i∈S]. Известное
тождество для суммы k наибольших чисел a_i ∈ [0,1]:

    TopKSum(a) = min_{0≤λ≤1} [kλ + Σ_i max(0,a_i−λ)].

Доказательство: правая часть ≥ суммы любых k элементов; при λ между k-м и
(k+1)-м по величине элементом достигается равенство, в том числе при связках.
Границы k=0,n в коде обрабатываются непосредственно.

Введём z_vi≥0, λ_v∈[0,1], r≥0. Решаем:

    min r
    Σ_i x_i = k, x_i ∈ {0,1}
    z_vi ≥ U_vi − (U_vi−L_vi)x_i − λ_v
    r ≥ kλ_v + Σ_i z_vi − Σ_i L_vi x_i   для всех v.

**Утверждение 3.** Оптимум MILP равен min_S R(S).

**Доказательство.** При фиксированном x минимум по λ,z в каждом независимом
блоке v равен точной сумме top-k из предыдущего тождества. Все ограничения
на r вместе равносильны r≥R(S). Минимизация по допустимым бинарным x завершает
доказательство. □

Нужны n бинарных и 1+m+mn непрерывных переменных, 1+m+mn ограничений.
Это компактность относительно числа вершин, не полиномиальное время MILP.
Число вершин тоже может расти быстро; реализация ограничивает d≤5.
При фиксированном S oracle стоит O(m n log n) с полной сортировкой в коде.

## 5. Сертификат и границы численного решения

**Следствие.** Для каждого мира в объявленном множестве потеря подборки S
не превышает R(S); свидетель (вершина, угол признаков, набор T) достигает этой
границы. В коде R(S) заново вычисляется oracle, независимо от значения r MILP.
Численно подразумевается допуск 1e−7, а не машинно проверенное рациональное
доказательство. При time limit возвращается достигнутый R(S) и нижняя граница
решателя: их разность ограничивает недооптимальность, статус не «optimal».
При отсутствии допустимого решения используем номинальный набор, lower bound
0 и явный fallback. Сертификат набора остаётся осмысленным, оптимальность — нет.

## 6. Почему общие приоритеты дают более точную границу

Консервативный аналог заменяет каждый итоговый балл независимым интервалом
[min_w w·ℓ_i, max_w w·u_i]. Все совместно реализуемые векторы баллов входят в
этот больший ящик. Поэтому для любого S имеем R_shared(S)≤R_box(S).
Следовательно, min_S R_shared(S)≤min_S R_box(S). Это сравнение границ в разных
множествах, НЕ обещание превосходства выбранного S по любому реальному миру.

Неравенство бывает строгим: два точных профиля (0.4,0.8), (0.5,0.9), k=1,
W — весь симплекс. Второй всегда лучше, R_shared({2})=0; независимые интервалы
[0.4,0.8] и [0.5,0.9] дают R_box({2})=0.3, выдумывая несовместимые приоритеты.

## 7. Какой вопрос задавать

Для каждого ещё не определённого сравнения a,b рассматриваем два ответа:
W⁺=W∩{w_a≥w_b}, W⁻=W∩{w_b≥w_a}. Связки покрываются обеими ветками.
Пусть M(W)=min_S R_W(S). Считаем C_ab=max(M(W⁺),M(W⁻)) и выбираем минимальный
C_ab среди допустимых пар. Это точный одношаговый minimax выбор В ЭТОМ классе
вопросов, если все решатели завершились с optimum; не оптимальная многотактовая
стратегия и не новая общая теория elicitation.

**Утверждение 4.** M(W⁺),M(W⁻)≤M(W).
Доказательство: для любого S максимум по подмножеству миров не больше исходного;
минимизация по тому же семейству S сохраняет неравенство. Аналогично для сужения
интервалов θ. □ При правдивом ответе истинный мир остаётся внутри. Если ответ
пропущен, ничего не сужаем и улучшение не обещаем; если противоречив — ошибка
валидации. Реализованная потеря в отдельном истинном мире может увеличиться
из-за смены минимаксного набора, хотя его худшая граница уменьшается.

## 8. Простой положительный и отрицательный пример

A=(.95,.50), B=(.50,.95), C=(.70,.70), k=1. Неизвестны два веса, их сумма 1.
Среднее выбирает A/B: худшая потеря .45. Minimax выбирает C: худшая потеря .25.
Но при истинных равных весах A/B имеют .725, C — .70: реализованная потеря
robust-выбора .025 против нуля у среднего. Именно поэтому нельзя утверждать
«наш алгоритм всегда точнее» или выбирать только выгодные метрики.

## 9. Ограничение потери номинального качества (добавлено после dev)

Пусть m_i — зафиксированная до уточнений номинальная оценка; B — обычные top-k
по m. Для заданного бюджета ε≥0 ограничим допустимые подборки условием

    Σ_{i∈S} m_i ≥ Σ_{i∈B} m_i − ε.

Это одно линейное ограничение MILP. B всегда допустима, поэтому точный guarded
оптимум имеет одновременно R(S_guard)≤R(B) и номинальную потерю не более ε.
В худшем случае вернётся B. Это гарантия относительно baseline в объявленной
модели, не гарантия среднего истинного качества. Для сравнения R_unconstrained*
≤R_guard*; ограничение защиты может ухудшать minimax-оптимум.

В ветках вопроса m,B,ε НЕ пересчитываются. Тогда допустимое семейство подборок
одинаково, и доказательство монотонности из §7 сохраняется. Если каждый раз
переопределять B по новым весам, это доказательство уже неприменимо.
В benchmark ε=0.01k: один номинальный пункт из 100 в среднем на профиль.
Число выбрано как понятный предел компромисса после dev_v2; старые результаты
и их код сохранены. Это не заявляется оптимальным гиперпараметром.
