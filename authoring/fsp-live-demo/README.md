# Живой обзор ФСП / Карьера

Метод выбран по пользовательскому примеру Geoscan: настоящий headless Chrome,
Playwright recordVideo, сценарные действия, подписи и маркеры, затем FFmpeg → MP4.
Это запись интерфейса работающего приложения, не анимация статичных снимков.
Без озвучки, музыки и системного курсора. Розовый маркер появляется у нажатий.

## Воспроизведение

Установить Node.js, Python 3, FFmpeg и Chromium. Версия Playwright закреплена:
`1.64.0-alpha-1790635538000`; проверена с Chromium Playwright build1247.

```sh
npm ci
export DEMO_CHROME='/absolute/path/to/chrome'
node smoke-record.cjs
node record.cjs /absolute/output/directory http://127.0.0.1:8035
python3 encode.py /absolute/output/directory /absolute/output/overview.mp4
```

`record.cjs` ожидает отдельный свежий экземпляр приложения с `FSP_DEMO_MODE=true`
и новыми данными. Он входит в оба демонстрационных аккаунта, отзывает начальное
приглашение через UI, проходит короткую проверку, формирует новое приглашение,
принимает его кандидатом и скачивает PDF работодателем. Эти действия сохраняются
в БД. Для репетиции добавляется `--rehearsal`; для следующего запуска нужна другая
свежая демобаза. Скрипт не удаляет базу и не исправляет её содержимое напрямую.

В данной съёмке использованы только отдельные локальные базы; пользовательский
стенд 8031 не менялся. Существующие тестовые профили вымышлены, их грейды до
съёмки взяты из seed. Короткая проверка показывает новый реальный результат и
не присваивает грейд. У seeded-профиля старая рубрика, поэтому новый результат
остаётся в истории до основной проверки актуальной рубрики; это видно в UI.

`solve-visible.py` — помощь оператору демонстрации: вычисляет числовые ответы
по публичным условиям задач, а не читает ключи оценивания. SQL выполняется на
показанной таблице в SQLite :memory:, Python-задачи считаются по их литералам,
API-задачи — по показанным таблицам. Сервер принимает ответы и оценивает попытку
через обычный UI. Это функциональная демонстрация, не независимая оценка банка.

`record.json` содержит границы сцен, ошибки браузера, проверки раскрытия
контактов, PDF и отсутствия горизонтального переполнения. Финальный монтаж
обрезает ожидание между сценами и переключает вид между двумя кабинетами.
В первой поисковой сцене пример Middle; затем условия явно меняются на Junior
и гибридный формат, чтобы пригласить того самого кандидата, который проходит
проверку. Данные и результаты интерфейса не перерисовываются.
