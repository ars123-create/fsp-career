# ФСП / Карьера — техническая документация

Версия 0.5.0, 10 октября 2026. Хакатонный прототип на вымышленных данных. Лобутев Арсений Константинович — разработка и алгоритмы; Просветов Александр Сергеевич — продукт, тестирование и презентация. Требования и ответы организаторов сохранены в REQUIREMENTS.md и ORGANIZER_QA.md.

## 1. Назначение

Кандидат создаёт профиль и подтверждает навыки. Работодатель формулирует потребность, получает объяснимую подборку и отправляет адресное предложение с зарплатой в рублях. Принятие приглашения или самостоятельный отклик дают именно этой компании доступ к контакту. Публикация вакансии для приглашения не требуется. ФСП ID не обязателен.

Покрытие: Python backend и аналитика данных / SQL, Junior и Middle. Такой объём разрешён организаторами. Корректность заданий проверена программно; повторяемость грейдов — в симуляции. Калибровка и оценка релевантности независимыми людьми не проведены. Окончательные решения о реальном найме система не принимает.

## 2. Архитектура

Браузер → React 19 / TypeScript / TanStack → FastAPI → SQLModel / SQLAlchemy → PostgreSQL 16. Для локального демо используется SQLite. Модульный backend обслуживает API и собранный frontend. Alembic применяет миграции. Docker Compose запускает приложение, PostgreSQL и Mailpit; порты по умолчанию доступны только локально.

Модули backend/app: auth — аккаунты; profiles и visibility — профили и права; assessments и assessment_bank — попытки и грейд; matching и mixed_matching — подбор; hiring — приглашения и отклики; pdf_profile — PDF; seed — вымышленные данные. Исследование отделено в research, адаптированное ядро — в mixed_engine.

Основные сущности: User, Candidate, Company, ActionToken, Attempt, Evidence, GradeAward, Need, Job, Invitation, Application, AuditEvent, LocalMail. Attempt хранит ответы, seed и версию рубрики; GradeAward ссылается на попытку; Evidence хранит подтверждения по семействам. При восстановлении Need заново проверяются публикация и права.

## 3. Аккаунты и приватность

Регистрация включает подтверждение email. Пароли хешируются Argon2. JWT имеет назначение, аудиторию, срок и версию сессии. Выход, сброс пароля и смена email отзывают старые сессии. В базе хранится хеш одноразового токена с назначением и сроком. Лимитер входа рассчитан на один процесс.

Согласия на обработку и публикацию имеют отдельные даты и версию. Отзыв публикации исключает профиль из новых поисков. Разрешение на контакт отзывается отдельно по приглашению или отклику. При другом действующем основании у той же компании доступ сохраняется. Зарплатная вилка обязательна; API отклоняет некорректные границы.

Функция candidate_view формирует разрешённые данные для API и PDF. До согласия скрыты имя, email, телефон и мессенджер. Кандидаты не читают чужие профили; работодатели не используют чужие приглашения и подборки. Ответы с персональными данными имеют no-store. Уже скачанный файл удалить с чужого устройства нельзя; отзыв действует на новые ответы и скачивания.

Публичные тексты проверяются на контакты и URL, но это не гарантирует анонимность произвольного текста. Юридическое соответствие 152-ФЗ техническими тестами не установлено. Публичный пилот требует политики, оснований обработки, сроков хранения и процедур оператора.

## 4. Проверка компетенций

Заявленный грейд отделён от подтверждённого. Основная форма: 12 заданий за 45 минут, включая 6 практических задач с двумя числовыми полями. Параметры, таблицы и порядок вариантов меняются по seed. Правильные ответы остаются на сервере до завершения своей попытки. Пользовательский код не исполняется. Сохранённую попытку можно продолжить после перезагрузки.

Рубрика 2026-10-v3: не менее 75% суммарно, 50% по каждому навыку и 50% практических задач по каждому навыку. В практической задаче оба поля должны быть верны. Старые попытки сохраняют собственную рубрику. Неудача не понижает достигнутый грейд. Интервал смены категории — 90 дней; пройденная внутри интервала попытка сохраняется для последующего применения.

Короткая проверка: 3 практических задания за 12 минут, раз в неделю, без смены грейда. Обновляется только проверенное семейство. Без совместимой основной формы результат сохраняется в истории, не заменяя общий профиль навыков. ФСП ID, зарплата и спрос грейд не меняют.

Для банка v2 сохранены 4800 проверок эталонов. В v3 исправлено семейство о повторе операции: эталон сверялся с SQLite COMMIT/ROLLBACK на 400 случаях и 630 допустимых перестановках. Это корректность вычисления, не доказательство сложности для людей. Подробности: ASSESSMENT_V2.md и ASSESSMENT_V3.md.

## 5. Алгоритм подбора

Сначала применяются обязательные условия: специализация, подтверждённый грейд, навыки, формат, зарплата и достижения. Текст потребности превращается в редактируемые условия. Неизвестные навыки не становятся выдуманными требованиями.

В интерфейсе 0.5.0 по умолчанию выбран mixed-kg-v1, или m6. Модель содержит шесть семейств предпочтений: линейное, геометрическое, степенные средние −2 и +2, насыщение и сочетание суммы со слабым звеном. Каждое представлено несколькими наборами весов. Байесовское обновление по ответам определяет ожидаемую полезность профилей.

До трёх сравнений условных сочетаний навыков выбираются по одношаговой ожидаемой пользе для пятёрки. Пропуск нейтрален, ответ можно отменить. История абсолютных векторов остаётся применимой после изменения пула. Защита от доминирования не позволяет выбрать строго худший по всем навыкам профиль вместо лучшего. Подтверждённое достижение разрешает равенство идентичных векторов. Грейд и доступ к контактам остаются отдельными.

Предел режима — 100 подходящих профилей и до трёх навыков. Сверх 100 API просит уточнить фильтры, не обрезая базу молча. Два одновременных численных расчёта ограничивают память. API без указанного режима сохраняет прежний evidence для совместимости. Также доступны прямые веса, линейное уточнение и устойчивый подбор. Балл не является вероятностью найма.

## 6. Метрики и ограничения

В фиксированном domain-исследовании выполнено 548352 запуска методов: 14 семейств сценариев, 6–100 профилей, 2–3 навыка, до трёх сравнений. Основная метрика — нормированный regret суммы полезностей пятёрки ×100, меньше лучше. m6: 0,955779; P15: 1,054081; GP: 1,158263; EVOI: 1,425472; PABBO: 2,076677; равная сумма: 2,313419.

Потеря m6 ниже на 33% относительно EVOI и на 17,5% относительно GP. Только m6 прошёл полный заявленный допуск. P15 не прошёл ограничения относительно GP в threshold и по общему интервалу. GP быстрее: p95 отдельного шага при N100/d3 — 0,018 против 0,234 секунды. Это не HTTP SLA.

Протокол отдельного domain-исследования составлен после прежних экспериментов; использованы новые seeds, старые результаты сохранены. Интервалы приближённые. Пересчёт статистик выполнен тем же агентом другой реализацией, не независимым оценщиком. Протокол, снимок 123 файлов и строки результатов, сжатые без потерь, находятся в research/frontier_2026. Нет доказательства мирового оптимума или лучшего найма людей.

Разрешённая организаторами симуляция test-retest: 4320 профилей, 8640 форм, 103680 ответов текущего банка. Обычные формы дают совпадение решений 85,6–88,3%; сильная разница сложности — 77,5–83,6%. Cohen κ: 0,573–0,665 и 0,304–0,546 соответственно. Это повторяемость подтверждения заданного уровня, не точность определения истинного грейда. История и cooldown не участвовали.

Способности и сложность гипотетические. Положительная разделяющая сила частично заложена моделью ответов. Пороги после результатов не менялись. Полные разрезы: GRADE_RETEST_0_5.md и output/validation/grade-retest-v1. Независимая оценка людьми — NOT RUN.

## 7. Проверки продукта

188 серверных тестов PASS на SQLite macOS, PostgreSQL и внутри Linux Docker-образа 0.5.0. Отдельно 15 проверок сравнивают адаптер с замороженным m6, включая 100 профилей, ответы, пропуск и исключение профиля. TypeScript/Vite собираются; предупреждение о крупном JS chunk сохраняется.

В новой записи 0.5.0 выполнены три практических задания, восстановление ответа после reload, m6 с заменой одной позиции, восстановление подборки, новое предложение 110–150 тысяч рублей, принятие, контакт и скачивание PDF. Аккаунты вымышлены. Новая регистрация без ФСП, основная форма из 12 заданий и два работодателя ранее проверены в 0.4.5. Версии доказательств разделены в E2E_0_5.md.

Docker-сборка прошла на VM 2 CPU / 2 GB с работающими сервисами. Первые две попытки получили код 137; ограничение JS heap до 256 MB позволило собрать образ. Новый контейнер отвечает с macOS. Проверки PostgreSQL, распаковки и итоговые статусы — RELEASE_0_5.md. Непроверенные свойства не обозначаются успешными.

## 8. Запуск и эксплуатация

Нужны Python 3 для настройки, Docker с Compose v2 и доступ к реестрам пакетов при первой сборке. Из корня: python3 scripts/setup.py, затем docker compose up -d --build. Приложение: http://127.0.0.1:8019; API: /docs; почта Mailpit: http://127.0.0.1:8026. При занятых портах используйте отдельные значения и имя Compose-проекта. Не удаляйте существующие volumes.

setup.py создаёт случайные секреты в .env, не перезаписывает существующие и не печатает их. В архив не входят .env, runtime-база, токены и чужие персональные данные. На главной доступны два демо-входа. Новая регистрация подтверждается письмом в Mailpit; письма наружу не отправляются.

Без Docker: sh scripts/start.sh, по умолчанию порт 8018 и SQLite. Проверено с Python 3.14 и Node 24; зависимости закреплены lock-файлами. Без SMTP в демо доступна приватная квитанция, не доказывающая владение внешним email. Для публичного пилота нужны HTTPS, SMTP, отключённые демо-входы, отдельная база, резервное копирование и политика обработки данных. Короткий нагрузочный сценарий m6: 100 профилей, 1/10/30 клиентов, два набора, 492/492 HTTP 200. p95 при 30 клиентах 0,84 и 1,40 с, без выявленных нарушений приватности/контракта. Длительная нагрузка и независимая машина не проверены.

## 9. Интеграции и компоненты

ФСП представлена явно обозначенным демонстрационным адаптером: официальный API и реестр не предоставлены. ID сам по себе не подтверждает достижения. ATS — концепция API и событий приглашения/принятия с повторной проверкой прав на контакт; работающая внешняя ATS не заявляется. Такой объём разрешён ответами организаторов.

HTTP-контракт: docs/openapi.json и /docs. Входы, выходы и ошибки описаны схемами app.openapi() текущей сборки. Исходники, миграции, контейнеризация и команды тестов включены в комплект.

Из Full Stack FastAPI Template (MIT, e99fbaeba3b55190156ebae525ad9d481d76677e) адаптированы небольшие части security и UI. Готовые Radix/shadcn-компоненты собраны по ранее созданному визуальному ориентиру. Лицензии NumPy/SciPy, FastAPI, SQLModel, SQLAlchemy, Alembic, ReportLab, pypdf и Manrope сохранены. Источники и проверки: REUSE_REGISTER.md, THIRD_PARTY.md, licenses. Сочетание методов не объявляется научной новизной.
