# Подготовленный пакет предметной проверки

Исторический снимок приложения 0.4.4-dev / банка v2. Подготовка и техническая проверка PASS.
В 0.4.5 изменено [одно семейство банка](ASSESSMENT_V3.md); этот пакет не
считается проверкой нового содержания. Генератор пакета отказывается работать
с изменённым снимком, сохранённые ZIP не переписываются. Для актуального банка
нужен отдельный протокол предметной проверки.
Ответов реальных оценщиков: **0**. Human validation и калибровка: **NOT RUN**.

Сформированы четыре архива для двух независимых оценщиков каждой специализации:

- [Python backend, оценщик A](../output/expert-review-0.4.4/backend-A.zip)
- [Python backend, оценщик B](../output/expert-review-0.4.4/backend-B.zip)
- [Аналитика / SQL, оценщик A](../output/expert-review-0.4.4/data-A.zip)
- [Аналитика / SQL, оценщик B](../output/expert-review-0.4.4/data-B.zip)

В каждом архиве 24 задания, читаемый TXT, JSON с полным контекстом, пустая форма
ответов и схема. В сумме — 48 различных заданий четырёх исходных форм:
2 специализации × 2 уровня × 12 заданий; 20 именованных семейств. Пакеты A/B
различаются порядком, а не содержанием. Это не 96 разных задач и не 48
независимых измерений. Текущие уровни, эталоны, seed и имена семейств в
передаваемые архивы не включены. Ключ координатора лежит отдельно и не должен
передаваться до завершения слепой части.

Оценщик решает задачи либо указывает причину отсутствия ответа, отмечает
неоднозначность/ошибки, связь с работой, сложность и замечания. Нужен опыт
соответствующей специализации. Один человек не считается двумя оценщиками.
Пакеты никому не отправлены; пользователь сообщил, что оценщиков пока нет.

Это разработческая проверка содержания, а не эмпирическое определение грейдов.
Задание на простую операцию допустимо в сложной форме; оценка сложности одной
задачи не назначает категорию кандидату. Имена пользователей и контакты для
этого этапа не нужны. Методика и seeds заданы до сбора ответов:
[DESIGN.md](../validation/expert_review/DESIGN.md).

## Воспроизведение и приём ответов

Из корня проекта, в существующем окружении приложения:

```sh
PYTHONPATH=backend .venv/bin/python -m pytest validation/expert_review/test_packet.py -q
PYTHONPATH=backend .venv/bin/python -m validation.expert_review.packet build --output /tmp/fsp-review-new
PYTHONPATH=backend .venv/bin/python -m validation.expert_review.packet collect \
  --packet output/expert-review-0.4.4 \
  --reviews /absolute/path/review-backend-A.json /absolute/path/review-backend-B.json \
  --output /absolute/path/collection-report.json
```

Выходная папка сборки должна быть новой: существующие ответы не перезаписываются.
Без `--reviews` получается корректный отчёт NOT RUN. Ответы не дописываются
автоматически, пропуски не заменяются нулями. Валидатор проверяет строгость
типов, диапазоны, форму числовых ответов, полный состав IDs и происхождение
записи. Повтор одного оценщика в одной специализации отклоняется.

Даже все заполненные формы с самоотчётом `human` дают только
`DECLARED REVIEWS RECEIVED`, а не подтверждённое качество банка. Координатор
проверяет происхождение ответов, независимость и содержание замечаний.
Искусственные фикстуры помечаются `synthetic_fixture`, не смешиваются с
человеческими и дают только TECHNICAL_SMOKE.

## Результат технической проверки

23 теста PASS. Проверены полнота контекста относительно банка, отсутствие
эталонов в архивах, воспроизводимость ZIP, различие порядка, сохранение
существующих черновиков, пустые формы, неполные/ошибочные ответы, повторные
IDs, изменение заданий, числовые NaN и разделение фикстур от заявленных
человеческих наблюдений. Наборы с декларацией `human` внутри тестов — тоже
искусственные проверки обработчика, а не полученные анкеты.

Отчёт: `output/validation/expert-review-tests.xml`.
Состояние сбора: `output/expert-review-0.4.4/collection-status.json`.
Хеши пакетов/инструмента и проверка неизменности приложения:
`output/validation/expert-review-ready.json`.

[Проверка внешних источников](EXTERNAL_DATA_AUDIT.md) не дала подходящего
открытого эталона нашего банка. Сложность, сопоставимость форм, пороги и связь
с работой по-прежнему не подтверждены на людях. Оценки приложения, банк и
замороженные результаты исследований при подготовке пакета не менялись.
