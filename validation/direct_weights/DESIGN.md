# Явные приоритеты работодателя

7 октября 2026. B05, R11–R13/R17/R18. Разделы 6/9 плана и требования
перечитаны. Основание — опубликованный аудит `research/elicitation_controls`:
универсальное преимущество вопросов над прямым вводом не установлено.
Аудит сохранён со своим адаптером в отдельном ZIP и не перенастраивается.

Готовые компоненты: NumPy 2.4.4 `average`, BSD-3-Clause (исходник, лицензия и
два официальных примера прочитаны/выполнены до аудита); существующие Pydantic
2.13.5 Field/model_validator и shadcn Input/Button/Dialog с сохранённым MIT.
Новых библиотек нет. Минимальные NumPy-примеры и исследовательский контроль
прошли проверку; ниже дополнительная изолированная адаптация на 1–3 навыка.

Контракт: режим `weighted`, `ranking.weights` — числа 0–100 для каждого
выбранного навыка. Пустой словарь означает явно показанные равные приоритеты;
ненулевой словарь обязан точно совпадать с нормализованным набором навыков.
Сумма должна быть положительной. Строки/boolean/NaN/Infinity/отрицательные
и лишние веса отвергаются. Пропорции нормируются, сумма 100 не обязательна.
Отсутствующие веса не угадываются. В остальных режимах веса не допускаются.

Шкала объясняется через одинаковый рост результата проверки 50→100 процентов
при прочих равных. Это предпочтение запроса, а не вероятность найма и не
подтверждение сопоставимости измерения навыков. Человек выбирает способ ввода.

Обязательные фильтры применяются прежним `evaluate` до ранжирования, в том
числе для навыка с нулевым весом. Выдаётся до пяти профилей по взвешенному
среднему наблюдаемых результатов. Округление для ничьей — 12 знаков в
нормированной шкале, затем существующее подтверждённое достижение и ID.
Грейд, зарплаты, контакты и публикация не изменяются. Веса сохраняются в
существующем JSON Need.ranking; миграция не требуется. Снимок старой подборки
и пересчёт сохраняют прежние правила доступа.

UI продолжает уже сгенерированный референс design/employer-reference-v1.png.
Используются действующие диалог/поля/кнопки/типографика. В режиме уточнений
можно открыть редактор с округлёнными текущими долями, проверить и применить
свои значения. До явного применения выдача не меняется. В прямом режиме
показываются действующие доли и переход к вопросам с новым пустым диалогом
предпочтений (прежние ответы не смешиваются с ручными весами).

Проверки до интеграции: ручная сумма и перебор малого top-k; одинаковые
пропорции/нули; 1–3 навыка; недопустимые формы/числа; неизменность входов.
После: API двух компаний и кандидата, обязательный нулевой навык, зарплата,
отозванная публикация, ФСП при ничьей, сохранение/восстановление, отсутствие
изменения грейда/контактных прав; UI ввод/ошибка/сохранение/reload/возврат.
Независимая оценка людей и превосходство способа ввода NOT RUN.
