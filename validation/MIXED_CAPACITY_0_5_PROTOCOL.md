# Mixed-KG m6: API на 100 профилях

Протокол зафиксирован 10 октября 2026 до первого запуска нового измерения.
Адаптация прежнего измерителя: режим mixed и ожидаемый идентификатор mixed-kg-v1. Остальные генераторы, seeds, запросы и пороги сохранены. Это проверка B09 / R23, не повторная оценка релевантности и не изменение
замороженных исследовательских наборов.

Два отдельных процесса приложения, каждый со своей временной SQLite:

1. `bank_v2`, seed 934001: 100 профилей, три навыка с баллами из 50/75/100,
   сумма от 225 до 275. Это искусственные записи на сетке текущей рубрики,
   а не ответы людей. Вектор 100/100/100 исключён заранее, чтобы задача выбора
   не сводилась к достаточному числу одинаковых максимальных профилей.
2. `varied`, seed 934002: 100 различных векторов с непрерывными баллами
   из [50,100], сумма не меньше 225. Нагрузочный случай большой вариативности;
   нынешние короткие формы не генерируют такую точность процентов.

Все профили опубликованы, без ФСП, Python backend / Middle / remote,
180–240 тыс. RUB. Это подготовленные фикстуры для замера, не полная проверка
регистрации/экзамена. Путь через UI проверен отдельно в E2E_0_4.md.
30 отдельных вымышленных работодателей с собственными сессиями; контакты не
разрешены никому. Рабочая база 8018 и Docker-стенд 8019 не используются.

Один uvicorn, штатный пул синхронных обработчиков Starlette. BLAS/OMP — один
поток на вызов. Сокет только 127.0.0.1, свободный порт выдаётся ОС.
HTTPX 0.28.1 AsyncClient, trust_env=false, до 30 соединений, timeout 40 секунд.
Три прогревочных запроса исключены явно. Затем уровни 1, 10 и 30 клиентов;
каждый выполняет шесть запросов без пауз: исходный запрос, ответ left,
исходный запрос, ответ right, исходный запрос, skip. Если вопрос отсутствует,
следующий запрос также исходный. Всего 246 измеренных запросов на набор.

Измерять полную задержку на клиенте, nearest-rank p50/p95/max, число HTTP200,
ошибки/тайм-ауты и семантические нарушения отдельно. Не исключать хвосты и
ошибки. Условный технический допуск: все запросы HTTP200, ноль нарушений
контрактов/приватности/skip и p95 < 2000 мс на каждом уровне. Число — цель
команды из PLAN_RU, не требование организатора и не SLA.

Наряду с задержками сохранять версию/хеш кода приложения, хеш протокола и
скрипта, версии библиотек, CPU/платформу, seed, уникальные векторы и сырые
строки измерений. Фиксировать остановку только созданного тестового процесса.
Временная БД удаляется при завершении; парольные секреты и JWT в отчёт не входят.

До основного замера воспроизвести изолированный smoke: 1 клиент / 1 запрос.
Если замер провалится, сохранить отрицательный результат. Для оптимизации
разрешено повторять этот нагрузочный набор с явной новой версией результата;
это performance-development, не новый независимый тест качества рекомендаций.
Код и протоколы `research/*` сохраняются неизменными.
