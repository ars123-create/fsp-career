# Короткая проверка обновляет проверенное семейство

7 октября 2026. B04/B05/B09, R04–R06/R12/R18. План и требования перечитаны.
В приложении 0.4.3 `apply_skills` заменяет весь профиль результатов одной
короткой формой. Одно задание на навык может заменить четыре результата и
сделать итог 0 или 100. Это установленная семантика кода, а не оценка людей.

Предлагается фиксированный набор семейств из последней успешной основной
проверки текущей категории и рубрики. По каждому семейству хранится последнее
наблюдение; повтор того же семейства заменяет его, не увеличивает покрытие.
Процент — среднее этих наблюдений, не оценка вероятности владения навыком.
После одной короткой задачи изменение ограничено 100/m пунктами для m
семейств; при m=4 — 25. Это арифметическое свойство, не психометрическая
валидность. Корректный повтор уже верного ответа не увеличивает балл.

Основная успешная проверка начинает новый набор. Неудачная основная проверка
не меняет действующую категорию и сохраняет прежнюю политику обновления;
короткая сохраняет и правильные, и неправильные наблюдения. Разные грейды,
специализации и версии рубрик не смешиваются. Новое неизвестное семейство
требует новой основной проверки, чтобы не менять знаменатель скрыто.

`checked_at` сводного навыка — дата самого старого из его действующих
наблюдений; одна свежая задача не омолаживает остальные. Дополнительно может
показываться дата самого нового наблюдения. Число семейств не объявляется
числом независимых измерений. История попыток/эталоны/грейды не пересчитываются.

Внутренний портфель не отдаётся в API/выгрузках. Его начальная база и каждое
наблюдение имеют ссылку на собственную попытку. Повтор завершения или
получения уже выданного грейда не откатывает свежие результаты. Перед
интеграцией нужен отдельный тест восстановления старых данных: допустимо
собрать портфель из однозначно упорядоченных записей той же категории и
рубрики. При отсутствующей базе/неоднозначном порядке прежние значения
сохраняются, короткий результат остаётся в истории, интерфейс объясняет
необходимость полной проверки. Ничего не угадывается по текущему проценту.

Готовые компоненты: Python 3.14.7 `copy.deepcopy`, `statistics.fmean`, PSF-2.0;
прочитаны документация и установленный исходник, лицензия сохранена ранее.
Проверены изолированные примеры копирования и среднего. SQLAlchemy 2.1.3
`row_number().over` / MIT изучен, но не выбран для ядра: одного порядка SQL
недостаточно для определения версии набора и атомарного обновления нескольких
семейств. Новая статистическая/ML-библиотека не нужна. Собственная часть —
малый адаптер предметных правил; научная новизна не заявляется.

До интеграции: независимая ручная арифметика, полный перебор двоичных
состояний четырёх семейств, повтор/противоречие/порядок, чужая категория,
другая рубрика, неизвестное семейство, атомарный отказ, неизменность входов.
Параметры и критерии записаны до запуска; пороги грейда/банк не подбираются.
Далее — API, две компании, сохранение категории, старая рубрика, миграция
пустой/непустой БД, UI сообщения и все прежние проверки.

Полезность реального найма, угадывание людьми, устойчивость к внешнему ИИ и
калибровка сложности остаются NOT RUN. Этот блок устраняет потерю свидетельств,
а не подтверждает полноту или профессиональную валидность банка.
