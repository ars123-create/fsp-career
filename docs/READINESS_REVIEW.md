# Можно ли считать проект готовым к победной сдаче

Обновление 8 октября: [комплект 0.4.5](RELEASE_0_4_5.md) включает новый полный
UI-проход и сборку из архива с 181 тестом. Качество найма людей и победа
этими техническими проверками не установлены. Ниже сохранены выводы прежнего аудита.

Исторический аудит 7 октября 2026. Ответ: **нет**. Есть локальный рабочий MVP 0.4.4-dev и
сохранённый комплект 0.4.0-dev, предшествующий ускорению, правилу равных оценок
и прямому вводу приоритетов, а также обновлению отдельных семейств. Техническая работоспособность
не доказывает качество оценки специалистов, релевантность найма и место на
конкурсе. Баллы конкурентов и решение жюри неизвестны; вероятность победы
из имеющихся проверок не вычисляется.

Последующий [аудит способов ввода](ELICITATION_AUDIT_0_4_2.md) выявил пробел
прежнего сравнения: преимущество над простым вводом приоритетов не установлено.
На 1200 новых задачах результат зависит от допущений об ошибках ввода; в пяти
сценариях из шести не установлено преимущество перед тремя фиксированными
вопросами. Это отдельная симуляция действующего адаптера, не оценка людей.

Продуктовый результат аудита — [прямой ввод в 0.4.3](DIRECT_WEIGHTS_0_4_3.md):
работодатель сам выбирает способ и может исправить предложенные приоритеты.
Техническая интеграция PASS, сравнительная полезность людям NOT RUN.

В [0.4.4](EVIDENCE_PORTFOLIO_0_4_4.md) устранена потеря остальных результатов
при короткой проверке. Миграция сохраняет прежние данные; повтор не увеличивает
покрытие. Это техническое исправление, не калибровка профессиональных навыков.

## Что должно измениться перед финальным выпуском

Подготовлены [пакеты слепой предметной проверки](EXPERT_REVIEW_READY.md):
четыре архива, 48 заданий, 23 технические проверки. Полученных ответов людей 0;
этот инструмент не меняет NOT RUN калибровки. [Поиск внешних данных](EXTERNAL_DATA_AUDIT.md)
не дал подходящего доступного эталона нашего банка.

1. **Проверяемое преимущество подбора.** Сильные baseline с одинаковым числом
   уточнений, заранее зафиксированный набор и отрицательные результаты уже
   опубликованы для v3. Дальше нужна независимая предметная оценка. Пользователь
   сообщил, что подходящих оценщиков пока нет; human validation остаётся NOT RUN.
   Не называть симуляцию исследованием найма.
   Прямой ввод весов проверен отдельно и интегрирован в UI/API 0.4.3;
   выбор способа ввода сохраняет фильтры и права. Это устраняет продуктовый
   пробел, но не заменяет независимую оценку релевантности и удобства.
2. **Убедительная оценка навыков.** Практические задания, больше семейств,
   независимые вычислительные эталоны и прозрачная версионированная рубрика
   реализованы в 0.4.0-dev. Число семейств не доказывает их статистическую
   независимость. Экспертная проверка сложности, границ Junior/Middle и
   сопоставимости вариантов остаётся отдельной непроведённой проверкой.
3. **Одна версия для демонстрации и сдачи.** Локальный комплект 0.4.0-dev
   проверен вместе с исходниками того выпуска и пустой временной БД;
   он предшествует ускорению 0.4.1-dev и предметному правилу 0.4.2-dev.
   Полный новый комплект ещё не собран.
   На коде 0.4.0-dev после упаковки пройден единый последовательный
   [UI-сценарий регистрации до контакта](E2E_0_4.md), включая проверку другой
   компании. Прямых изменений БД в этом сценарии не было; проверявшийся
   тогда код совпадал с выпуском 0.4.0-dev.
   Публичные ссылки и отправка ещё не подтверждены. Детали — RELEASE_0_4.md.

Обязательные слайды 7–11 сохраняются; поля команды остаются пустыми по прямому
указанию пользователя. Ветка research/preference_topk проверяет способ
выбора вопросов по собственному заранее зафиксированному протоколу.
Позднейшая интеграция описана отдельно, её отличие от эксперимента явно указано.

Дополнение по завершённой в этом аудите проверке: у новой ветки 53 теста PASS;
заранее зафиксированный heldout — 1600 синтетических задач. На основной группе
600 задач средняя потеря ниже сильного BALD на 21.1% (абсолютно 0.11 балла на
шкале условной полезности 0–100). Есть проигрыши при иных предпочтениях;
независимая оценка людьми NOT RUN, техническая интеграция PASS. Это продвижение по
первому пункту, но не основание менять общий вывод о готовности.
