# Проверка точного переиспользования расчётов назначения

Версия cache_v1, 7 октября 2026. Дополнение после просмотра test_v1, которое не меняет проверяемую политику выбора заданий и её результаты. Проверяет эквивалентность вычисления VOI и стоимость его вычисления. Не является новой отложенной проверкой качества подбора.

Перед реализацией изучены SciPy linear_sum_assignment и первоисточник Michael et al., Global Sensitivity Analysis for the Linear Assignment Problem (2020), https://arxiv.org/abs/2005.11792. Известность анализа чувствительности явно учитывается: простое разложение по единственному изменяемому столбцу не объявляется новым общим алгоритмом назначения.

Конструкция: для кандидата i предварительно вычислить оптимум без него C_i и оптимум R_ji без него и работодателя j. Тогда для любого нового столбца w_i значение назначения равно max(C_i, max_j(R_ji + w_ji)). Это следует из разбиения допустимых назначений по работодателю, которому достался кандидат, либо по отсутствию назначения.

После подготовки кеша VOI одиночного вопроса и пары вопросов одному кандидату считается без нового решения всей задачи для каждого исхода. Подготовка требует n(m+1) вызовов оптимизатора плюс один базовый. Поэтому при большом m она может быть дороже прямого метода; ускорение не гарантируется.

Проверка до публикации:

- Сравнение значения назначения с прямым SciPy на случайных прямоугольных задачах, отрицательных весах, запретах и пустом множестве работодателей.
- Сравнение точных VOI одиночных и парных запросов; пары разных кандидатов явно не поддерживаются.
- Benchmark seeds 2000–2019, размеры (кандидаты, потребности): (8,4), (40,8), (120,40), сценарий leakage, параметры модели как test_v1.
- Одна начальная проверка каждого навыка; затем измеряется оценка ВСЕХ одиночных запросов и пар разных навыков/семейств одного кандидата из фиксированного списка двух семейств на каждый из трёх навыков.
- Сначала точность: максимальное абсолютное расхождение ≤ 1e-9. Потом время: отдельно одиночный расчёт и одиночный+парный; подготовка кеша включается в оба сравнения.
- Порядок прямого и кешированного измерения чередуется по seed; первые вызовы библиотек прогреваются. Публикуются все размеры, включая ухудшения. Метрика времени: медиана попарного отношения direct/cached по seed.
- Хеши кода/протокола фиксируются до запуска. Старые core.py, PROTOCOL.md и test_v1.json не меняются. Кеш не интегрируется в приложение автоматически.
