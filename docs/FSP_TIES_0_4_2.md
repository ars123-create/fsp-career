## Исправленная предметная граница

В режиме уточнений 0.4.1-dev одинаковые оценки разрешались только порядком
ID. Из шести одинаковых профилей шестой с подтверждённым достижением мог
оказаться вне top-5. Обычный режим учитывал ФСП, а этот режим оставлял его
лишь фильтром. Это расходилось с правилом плана: при равных остальных
данных подтверждённое достижение усиливает профиль (B05, R07/R12).

Теперь ключ порядка: **оценка навыков → наличие подтверждённого достижения
с источником → стабильный ID**. Оценка сохраняет прежнее округление до 12
знаков в нормированной шкале. Даже минимальное различие после этого
округления имеет преимущество перед достижением. Число записей не даёт
дополнительного преимущества. Нет нового численного бонуса к навыкам.

Один ФСП ID, pending, неподтверждённость, отзыв и пустой источник не дают
приоритета. Демо-достижения остаются явно вымышленными; официальная интеграция
ФСП по-прежнему отсутствует. Грейд, обязательные фильтры, возможность искать
работу без ФСП и правила доступа к контактам не менялись.

Использован встроенный Python sorted. Сначала выполнен официальный пример,
затем отдельно проверен предметный прототип, затем он побайтно перенесён в
`backend/app/ranking_ties.py`. Старый адаптер сохранён в
`validation/ranking_ties/archive/`. Модель весов, выбор вопросов и замороженные
исследовательские ядра не редактировались. Это уточнение предметного правила,
а не новая научная модель или подтверждение качества найма.

На существующем вымышленном стенде выбран Python backend / Middle /
удалённая работа / подбор с уточнениями. Подходят 7 профилей, показываются 5.
Данные кандидатов не подгонялись и не менялись для показа.

| Действие | Наблюдаемый результат |

срабатывает ранняя остановка. Польза каждого ответа не гарантируется:
ветвь А в этом примере только уточняет порядок предпочтений.
