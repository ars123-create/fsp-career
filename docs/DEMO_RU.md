# Демо и комплект сдачи

## Запуск и проверка за 5 минут

1. `python3 scripts/setup.py`, затем `docker compose up -d --build`. Открыть http://127.0.0.1:8019. Для внешнего проверяющего это локальная инструкция, не публичная ссылка.
2. Нажать «Кабинет кандидата». Показать профиль, закрытые контакты, категорию, историю. Можно начать новую проверку из 12 заданий (6 практических), ввести два числовых ответа, нажать «Сохранить ответ», обновить страницу и продолжить. До сохранения черновик не считается ответом. В истории показать разбор ошибки. При неудаче старый грейд остаётся.
3. Выйти, зайти в «Кабинет работодателя». Выбрать Python backend, Middle и «Подбор с уточнениями», остальные условия оставить свободными: в демо есть 8 подходящих профилей. Показать два условных сочетания навыков; ответить, отменить ответ, пропустить другой вопрос. Пропуск не меняет приоритеты. Сохранить потребность, открыть её снова. Можно сразу перейти к специалистам без ответов. В режиме «По результатам проверок» отдельно показать запрос `Python backend, SQL, Middle, удалённо, 180–250 тыс`, нормализованные фильтры, основания и PDF без контактов.
4. Для пути контакта использовать демо-кандидата Junior: запрос `Python, Junior, гибрид`. Уже есть первоначальное приглашение от «Орбита Технологии». Дополнительное предложение можно отправить другому профилю.
5. Выйти → кандидат → «Приглашения». Показать компанию и вилку 110–150 тыс. Принять предложение. Вновь работодатель → «Приглашения»: контакт этого кандидата открыт. Отзыв отключает новые запросы по этому основанию.
6. Новая регистрация: адрес example.org, вымышленное имя. Письмо приходит в локальный Mailpit http://127.0.0.1:8026. Без подтверждения вход запрещён. Не используйте реальные данные на демо.

Состояние сохраняется в БД. Если предложение уже принято во время предыдущей репетиции, показать текущий статус и отзыв, а не редактировать БД вручную. Для чистой репетиции использовать отдельный Compose project/volume с другими портами, не удалять существующий volume.

Проверенная репетиция 0.4.2-dev на текущем стенде 8018: Python backend →
Middle → Удалённо → Подбор с уточнениями, ФСП-флажок выключен. Здесь 7
подходящих профилей. Вариант А (SQL 100 / API 50) сохраняет пятёрку;
«Отменить последний ответ» → вариант Б (SQL 50 / API 100) заменяет один
профиль. Сброс → пропуск сохраняет исходный состав. Это показывает конкретный
эффект ответа и его ограничение: не каждый ответ меняет список. На чистой
базе или после новых регистраций число профилей и сами пары могут отличаться;
не обещать заранее определённые буквы/ID. [Снимки и точные результаты](FSP_TIES_0_4_2.md).

## Каркас выступления, 4–5 минут

Дополнение 0.4.3 на стенде 8018: при Python backend / Middle / Удалённо
выбрать «Задать приоритеты самому» → «Изменить приоритеты» → 10/10/80 для
Python/SQL/API. В проверенном состоянии один профиль меняется. Сохранить
подборку, reload → «Мои подборки» → открыть её → «Обновить состав»:
приоритеты сохраняются. «Уточнить через вопросы» начинает новый диалог;
после ответа можно открыть редактор предложенных долей и исправить их.
Число профилей зависит от БД. [Проверенный сценарий](DIRECT_WEIGHTS_0_4_3.md).

- 0:00–0:30. Проблема: заявленное в резюме трудно сопоставить с потребностью команды. Решение соединяет проверку, подтверждения и предложение с согласия кандидата.
- 0:30–1:30. Кандидат: профиль, отдельная оценка, одно практическое задание с числовыми полями, история и отсутствие автоматического понижения.
- 1:30–3:00. Работодатель: потребность, исправляемые фильтры, факты в объяснении, условия до знакомства, принятие и контакт конкретной компании.
- 3:00–4:00. Проверки: API/PDF/два работодателя/гонки, локальная нагрузка, синтетические сценарии. Показать EVOI и сильные baseline при одинаковом бюджете. −0,1101 модельного балла к BALD в основной синтетической группе; проигрышные условия — на следующем слайде. Это не эффект на найм.
- 4:00–4:30. Границы: два направления, некалиброванный банк, demo ФСП, нет внешнего API и пилота. Дальше — экспертная разметка и интеграция.

Точный лимит защиты из предоставленного ТЗ неизвестен. Данные команды по просьбе пользователя не заполняются.

## Перед загрузкой на платформу

В `output/submission-0.4.4-dev/` подготовлены текущие исходники с README,
документация DOCX/PDF на 7 страниц, презентация PPTX/PDF на 15 слайдов и
112-секундный видеогид. Это монтаж финальных слайдов с реальными снимками,
без озвучки и без заявления непрерывной записи. Исходные заготовки 7–11
сохраняются по оформлению и структуре на финальных слайдах 1–5. Сведения о
команде остаются пустыми по явному указанию пользователя.
[Аудит комплекта и актуальная матрица](RELEASE_0_4_4.md).

В демонстрации 0.4.4 можно дополнительно показать список семейств в профиле:
короткая проверка обновляет проверенное семейство, сохраняя остальные и
прежний грейд. Пример 100% → 75% относится к специальному вымышленному
сценарию: сначала все правильные ответы полной формы, затем неверный ответ
одного из четырёх семейств каждого навыка. Это проверка арифметики и
сохранения данных, а не измерение изменения способности человека.

Старый комплект 0.4.0-dev сохранён; он предшествует ускорению 0.4.1,
правилу равных оценок, прямым приоритетам и сохранению семейств.

Не выполнено автоматически: публикация репозитория/хостинга, загрузка на платформу, подтверждение промежуточного срока и окончательная сдача. В переданных материалах нет учётных данных платформы, адреса Git remote и выбранного публичного хоста. Финальный дедлайн по сообщению — 11 октября до 23:59 МСК, внутренний ориентир загрузки — 20:00.

Материалы организаторов сохранены в materials/ без изменений. Пароль к исходной папке не включён в документы или поставку. Правила хакатона по использованию открытого кода/ИИ, кроме переданных материалов, не предоставлены; происхождение кода раскрыто в THIRD_PARTY.md.
